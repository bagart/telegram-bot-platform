# Схема расписания модулей: реестр + overrides

## Дизайн
1. **Реестр `telegram.modules_schedule`** (`config/telegram.php`, пустой по умолчанию): каждый модуль в своём ServiceProvider `register()` сам регистрирует задачи рядом с существующими саморегистрациями (providers/seeders/frontend_pages). Запись — массив:
   ```php
   ['command' => 'tts:prune', 'expression' => strval(config(...default...)), 'enabled' => (bool) config(...)]
   ```
   `enabled` = модульный feature-флаг (существующие ключи конфигов), по умолчанию true. Замыканий в записях нет → безопасно для `config:cache`.
2. **Пользовательский файл переопределений `config/schedule-overrides.php`**: карта `command => ['expression' => ..., 'disabled' => true]`, дефолтно пустая с прокомментированными примерами. Это единственная точка правки периодичности пользователем; переживает обновления модулей (в отличие от копируемых пресетов).
3. **`routes/console.php`**: демон-блок остаётся как есть; пять хардкодных блоков модулей заменяются циклом по реестру с применением overrides: `disabled` → пропуск, иначе `->cron(expression)->name($command)->withoutOverlapping()` (+ `when(enabled)` из записи реестра).

## Регистрации (перенос текущего поведения 1:1)
| Модуль | Команда | Дефолтное выражение | Флаг |
|---|---|---|---|
| menu | `menu:roles:sweep` | `0 0 * * *` (daily) | — |
| summarizer | `summarizer:digests` | `telegram.schedule.poll.expression` | `telegram.schedule_summarizer_enabled` |
| stt | `stt:prune` | `0 0 * * *` | `telegram.schedule_stt_prune_enabled` |
| tts | `tts:prune` | `0 0 * * *` | `tts.schedule_prune_enabled` |
| mafia | `mafia:sweep` | `* * * * *` | `telegram.schedule_mafia_sweep_enabled` |

## Тесты
Хост-фича `tests/Feature/ModuleScheduleTest.php`: после boot проверить наличие всех 5 задач в `Schedule::events()` с ожидаемыми выражениями и именами; кейс override: `schedule-overrides.summarizer:digests.expression` меняет расписание, `stt:prune.disabled=true` убирает задачу; флаг из модульного конфига выключает регистрацию.

## Верификация
Целевые Pest suites (host Feature + затронутые модули), pint --test, LF-only. Доки модулей (TTS Readme ссылается на routes/console.php) — поправить упоминания на реестр одной строкой.
