# ADR-004: Module Surfaces and Ownership

> Status: accepted
> Date: 2026-10-08

## Context

Seven grilling questions from the module-extensibility effort (and one adjacent inline session) all concern where a module's externally visible surface begins and ends, and who owns it when two modules claim the same surface. They were forced rather than optional: `/report` is registered twice on the flat command registry (antispam and nettools) with only prose comments in `config/tg_modules.php` asserting ownership, and live evidence showed the effective winner flips with deployment state — on an unsynced bot the flat last-wins registry hands `/report` to nettools, so the documented owner was not the runtime owner. The in-chat panel question exists because "menu" was explicitly in the user's scope and in-chat inline panels are the one menu-adjacent seam with zero contract: four independent callback grammars, no registry, no namespacing rule, and a selector that runs every `support()`-matching processor with no central collision guard.

The proxy Mini App question was forced by git archaeology: the committed product SDD, module Readme, docs index and root AGENTS.md all promise a 5-page Mini App, while `ProxyWebApiHandler` was never registered at any revision and was then deleted inside a formatting-only commit carrying no decision record — 4 of 5 tabs are dead at HEAD and no ADR, task or roadmap entry answers restore-vs-cut. Two implementation sub-choices inside the restore scope (the chunk build pipeline and the shared `MenuCatalogRefiner` route constraint) had to be settled before the restore answer could be phrased verbatim. The adopted-module wiring question was forced by audit gap G2: D1 (adoption tooling) was sized as "generate ~6 host artifacts" while three already-resolved wiring constraints (K20 prod-manifest fullness, K21 dev-path/prod-VCS lock flow, K22 package + force-env CI availability) define what "wired" means and put lock/baseline regeneration in user-owned tooling. The namespace-validator strictness question is the direct sub-decision of the panel question's option 2 — the proposed `<module>:` rule starts RED against 7-of-8 legacy namespaces, so someone had to choose migrate vs grandfather vs warn, and where it may block. Finally, a pre-existing missing import in antispam's `CaptchaJoinProcessor::moduleId()` surfaced as an ownership question when a summarizer tests-only task hit a production fatal: fixing it crosses a module boundary another workstream owns.

## Decision

### `/report` ownership: rename nettools' flat claim to `/netreport` (source question: `report-command-ownership`, resolved 2026-10-07)

**Option 2.** Nettools' flat `/report` claim is renamed to `/netreport` (`ReportCommand.php:27,30` plus the five catalog/docs sites `CommandMap.php:31`, `CommandCatalog.php:33`, `NtCards.php:95`, `MyCommand.php:31`, `Readme.md:5`; the token must match `parseCommandName()`'s `[A-Za-z0-9_]+` — `nt:report` is infeasible), and **plain `/report` stays with antispam** per `config/tg_modules.php:96-101` and the mirrored omission comment `:303-304`. Enforcement = removing the duplicate flat registration (flat fallback and route table then agree on every bot regardless of sync state) plus a duplicate-Telegram-command rule in `tg:modules:validate`, bundled with W-D1 as hardening (gate-matrix edge 11) rather than a separate workstream. Rejected: option 1 (registry precedence) is explicitly not part of this bug fix — it needs a TDD precedence contract on the 2026-10-01 bot-scope semantics and a deliberate bot-lib dispatch change reaching every module; option 3 (mandatory sync) stays separate engine work pending live route-row reconciliation; options 4–5 rejected for inverting documented intent / keeping the nondeterministic winner. Binding: B4a (antispam counter/docblock) remains independent Wave-1 work; the exact rename token may be adjusted inside the B4b task file without changing this decision, and B4b is gated on this answer.

### In-chat panel contract: minimal convention, no shared contract (source question: `in-chat-panel-contract-scope`, resolved 2026-10-07)

**Option 2 — minimal convention now.** Mandatory callback namespacing per module (`<module>:<action>`) is codified as a `tg:modules:validate` rule (or, if the arch-test branch is taken, a Reflection-based arch test per K23 — never `toImplement` on platform classes), with **no** shared rendering/keyboard contract and no migration of the four working grammars. Rejected: option 3 (full shared panel contract) for now — no demonstrated shared demand, and if ever revisited it may only be placed in bot-lib / `telegram-platform-lib`, the menu-package home being forbidden by the resolved `settings-write-contract-surface` decision (K7); option 1 (defer) was superseded by round-2 evidence that nothing keeps the 8 existing namespaces disjoint. Binding: the strictness sub-choice (strict-migrate vs grandfather vs warning-first) and the blocking-vs-report-only wiring remain owned by `namespace-validator-strictness` and `baseline-check-gate-registration-policy`; they must land before W-Q2 implements the rule but do not change this scope decision.

### Proxy Mini App API surface: RESTORE (source question: `proxy-miniapp-api-surface-restore`, resolved 2026-10-07)

**Option 1 — restore, executed as the rounds 8–9 "shipping task" (not a file resurrection), decided 2026-10-07.** The evidence-backed reading: committed, never-retracted product contract (proxy `sdd/README.md:13,364`, `Readme.md:38`, `docs/INDEX.md:3`, `AGENTS.md:236`) versus a deletion that carries no decision record — so restore, with this decision as the record that makes the re-add non-silent. Scope of W-Q3: register `webUi(ProxyUi::class)` in `ProxyOperationsModule::register()`, add a `publishes(..., 'proxy-assets')` leg mirroring `MafiaServiceProvider.php:109-111`, port the build trio + reshape routes per `proxy-restore-subchoices` (**A1 + B1**, decided in the same pass), adapt the 7 CHANGED / supply the 3 MISSING chunk API calls, add route tests following `tests/Feature/Web/ProxyInventoryHandlerTest.php`, fix stale `sdd/README.md:159` (and keep `:364,:372` accurate), and use the three-tier acceptance ladder 401 → 404 `module_disabled` → resolved as DoD (module must be activated in tests). Rejected: option 2 (cut the tabs) remains valid only if accompanied by an explicit amendment of those four contract documents; option 3 (verify runtime first) — its remaining authenticated leg is an implementation acceptance step, unrunnable in the current environment (Docker engine stopped).

### Proxy restore sub-choices: A1 + B1 (source question: `proxy-restore-subchoices`, resolved 2026-10-07)

**A1 + B1, decided 2026-10-07** (downstream of the restore decision, decided in the same pass).

**A1 — port the mafia trio:** `package.json` with `build: node tools/build-chunk.mjs`, `tools/build-chunk.mjs`, `vite.proxy-chunk.config.mjs` into `misc/BAGArt/tgbot-module-proxy`, resolve vite from the host `node_modules` exactly as mafia does (zero new npm dependencies — tension T7 dissolves), and add the missing publish leg (`publishes(..., 'proxy-assets')` mirroring `MafiaServiceProvider.php:109-111`); this makes `ChunkAsset.php:23`'s message true and closes the demonstrated staleness gap. Rejected A2 (keep hand-committed bundles): no rebuild path exists for the mandatory 7 CHANGED / 3 MISSING `main.ts` adaptations — it degenerates into hand-editing a minified 14 KB artifact, the pattern already proven to rot.

**B1 — adapt proxy routes to the refiner:** keep W-Q3 proxy-local — express the four currently-incompatible operations as `GET|POST|PUT` routes on **distinct paths** (path-only dedupe means a verb swap alone is insufficient; follow the nettools `GET chat-settings` + `PUT chat-settings/apply` precedent), drop the dead `_method` payload, and update the four matching chunk call sites in the same change; do **not** touch `MenuCatalogRefiner` (shared blast radius; verified bite is only 4 error-severity catalog findings, since dispatch uses the handler's own `routes()` and `apiBits` is unchanged for all-Admin routes). Rejected B2 (relax the shared refiner): it would change lint semantics for every module's webApi surface and needs its own compatibility audit, while the benefit is far smaller than framed. Binding flip condition: if route adaptation distorts the API beyond what the chunk can cleanly call, B2 is raised as its own menu-package task with its own tests — never a silent side effect of W-Q3.

### Adopted-module package wiring: validate + document (source question: `adopted-module-package-wiring-scope`, resolved 2026-10-07)

**Option 2 — validate + document.** The adoption command generates only the safe host artifacts (the `ModulesPagesGenerateCommand` precedent set: `config/tg_modules.php` entry scaffolds and Inertia page wrappers), machine-validates everything K20/K21/K22 define as "wired" (dev path-repo entry, PSR-4 mapping, prod VCS repository + `require`, rewrite-map entry, phpunit force/server env pins, host testsuite, root test chain, stale-lock detection — deferring to `cmd/deps/check` and `tg:modules:validate` wherever those already cover it), and prints the user-owned steps (`bash cmd/deps/update --mode=both`, reviewed-baseline regen, nested push, Docker/CI/doc rows) as an exact command checklist. It never runs composer, lock, or baseline mutations itself. Rejected: option 1 (generate everything) is contract-forbidden, not a preference — the dependency-operations rule routes all such work through `cmd/deps/*` with reviewed-baseline regeneration, and K20/K21 put both lock regenerations in the user-owned `cmd/deps/update --mode=both` flow; option 3 (generate host + document package wiring only) is strictly dominated by option 2 — it documents no more while leaving audit gap G2 unenforced and the K20–K22 checklist free to rot. Binding: the W-D1 task file must size against adoption-dryrun's 25 touch points using the generate-4 / validate-13 / document-8 split, and its `Requirements:` must cite K20/K21/K22 (closing audit gap G2).

### Namespace validator strictness: grandfather + new-only, report-only then blocking (source question: `namespace-validator-strictness`, resolved 2026-10-07)

**Option 2 with wiring (b).** Grandfather the 7 legacy namespaces (`wsi`, `wsa`, `sm`, `tv`, `tc`, `nt:`, `m:`) as an explicit exempt list with an owner/audit note, enforce mandatory `<module>:` for new or changed declarations, and ship the rule report-only first; wire it as a blocking step in `.github/workflows/module-validation.yml` only after W-D1 repairs that workflow — never register it in `bin/baseline-check` (venue policy = `baseline-check-gate-registration-policy`, whose recommendation matches and whose opening of wiring (a) would require reopening K25/K24/K29/K28). Scope the rule to the namespace check only: the `report` duplicate stays with `report-command-ownership`. Rejected: option 1 (strict migrate now) — hard-coupled to the `/report` decision, forces user-visible keyboard breakage across 4+ working modules with no callback inventory to scope the blast, and is blocked behind W-D1's CI repair anyway; option 3 (warning-first) is strictly dominated — same day-one safety as grandfathering but enforces nothing going forward, which is the very gap that flipped the panel decision to "minimal convention now". Binding: this is the verbatim sub-answer for the panel decision — "namespace check = grandfather + new-only, wiring = report-only now → blocking after W-D1 repairs `module-validation.yml`"; strict migration of the 7 legacy namespaces remains a possible later wave, decided separately if/when the owner wants the grandfather list emptied.

### Antispam `moduleId()` missing import: fix it (source question: `antispam-moduleid-missing-import`, resolved 2026-10-01)

**Fix (option 1), 2026-10-01.** Missing `use BAGArt\TelegramBotAntispam\AntispamPipeline;` added to BOTH affected processors: `Processors/CaptchaJoinProcessor.php` and `Processors/CaptchaCallbackProcessor.php` (same defect, latent in the callback path). Regression guard: `tests/Unit/ModuleProcessorSurfaceTest.php` asserts `moduleId()` resolves for every processor — the selector exercises this on every gated update, so a broken class reference is a production fatal. Rejected: option 2 (defer to the antispam owner / a separate task) leaves the dependent suite red and weakens the very D1 coverage it was meant to prove; option 3 (keep the test but bypass the shared selector) does not actually prove dispatch and hides the production fatal from the test suite. Binding: the fix crossed the "tests-only, summarizer src excepted" boundary deliberately, as a one-line missing-import fix with no semantic change; the regression guard must stay.

## Consequences

**Contracts touched.** `TgCommandRegistry` flat registration semantics (duplicate `/report` claim removed; the registry's last-wins behavior itself is deliberately left unchanged, with a duplicate-Telegram-command validator rule added instead); `TgModuleRegistrar::webApi()` / `webUi()` registration surface (proxy gains the `webUi(ProxyUi::class)` call and a `webApi` surface beyond `GET inventory`); `MenuCatalogRefiner` contract explicitly *not* changed — proxy adapts to its `GET|POST|PUT` + path-only-dedupe rules; `tg:modules:validate` grows rules (duplicate command, `<module>:` namespace) with day-one grandfathering; `.github/workflows/module-validation.yml` becomes the blocking venue once repaired; `config/tg_modules.php` declaration comments become enforced rather than prose; host `phpunit.xml`, rewrite-map, `composer.prod.json` and the `cmd/deps/*` locks stay user-owned and outside any generator; the antispam processor surface (`ModuleProcessorSurfaceTest`) now guarantees `moduleId()` resolves for every processor.

**What depends on these decisions.** W-Q3 (proxy restore shipping task) depends on the restore decision plus A1/B1; W-Q2 (namespace rule implementation) depends on both the panel scope decision and the strictness/wiring decision; W-D1 depends on the adoption-wiring scope for its `Requirements:` sizing and is simultaneously the precondition for the namespace rule going blocking and the venue for the duplicate-command hardening; B4b (the `/report` ownership mechanism work) is unblocked by the `/report` decision, while B4a stays independent Wave-1 work; the panel decision's rendering-contract branch remains closed unless revisited, in which case only a bot-lib / `telegram-platform-lib` home is admissible (K7).

**Follow-ups.** Strict migration of the 7 grandfathered namespaces is a possible later wave, to be decided separately. The route-sync root-cause fix (mandatory sync at activation/deploy) remains separate engine work pending live `bot_module_routes` reconciliation. Registry-precedence dispatch work remains a deliberate, test-first bot-lib change, not a bug fix. `baseline-check-gate-registration-policy` is still the venue-policy authority: no namespace or duplicate-command rule may be registered in `bin/baseline-check` without reopening K25/K24/K29/K28. If route adaptation in B1 proves to distort the proxy API, B2 (refiner relaxation) becomes its own menu-package task with its own tests. The four proxy contract documents must be amended together if the restore scope ever changes back to cutting tabs.
